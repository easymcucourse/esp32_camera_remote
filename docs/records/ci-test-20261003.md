# 2026-10-03 CI 与可移植构建

本轮补齐自动检查入口，未修改运行时功能，未烧录、擦除 NVS 或改变设备配置。

## 实现

- `.github/workflows/ci.yml`：push / pull_request / workflow_dispatch；只读权限、同分支取消旧运行。
- 主机作业：Clang Debug、ASan / UBSan、全部 CTest 与离线文档链接检查。
- 固件作业：ESP-IDF 5.5.1，LCD / ATOM × debug / release 四项矩阵；单项失败不取消其他项。
- `tools/ci_build.py`：独立构建目录 / sdkconfig，读取工程默认值与 CI 覆盖；检查模拟开关符合档位，release 检查模拟函数没有链接；生成 size.json。
- 保存应用、bootloader、分区表、ELF、MAP、flash_args、sdkconfig 与大小报告。
- `tools/check_doc_links.py`：仓库文档的内联文件链接与标题锚点、重复标题、中文 / URL 编码及显式锚点；跳过外部网址和围栏示例。失效链接返回非零。没有联网验证外部网址，也不声称支持所有 Markdown 语法。

使用方式与输出目录见 [构建说明](../development/build-and-flash.md#可移植-ci-构建)。Action 参数依据 [Espressif CI Action](https://github.com/espressif/esp-idf-ci-action/tree/v1)，容器依据 [ESP-IDF 5.5.1 Docker 文档](https://docs.espressif.com/projects/esp-idf/en/v5.5.1/esp32/api-guides/tools/idf-docker-image.html)。

## 本机证据

Windows、ESP-IDF 5.5.1 / Python 3.11；独立目录首次由 sdkconfig.defaults 生成，没有复用根工程 sdkconfig。

| 检查 | 结果 / 本地日志 |
| --- | --- |
| 主机 CTest | 42/42 通过；新增 doc_links 验证失效文件 / 锚点与退出码 |
| 工作流语法 | YAML 解析成功，触发器和四项矩阵核对通过；不等同 Actions 执行 |
| LCD debug | 构建通过，`build/ci-lcd-debug-validation.log`；最终报告 `build/ci-lcd-debug-final.log` |
| ATOM release | 构建及模拟符号排除通过，`build/ci-atom-release-validation.log`；最终报告 `build/ci-atom-release-final.log` |
| LCD release / ATOM debug | 独立构建通过，`build/ci-lcd-release-validation.log` / `build/ci-atom-debug-validation.log`；LCD release 模拟符号排除通过 |

每种配置重新使用时保留自己目录内的 sdkconfig；如果人为改动档位，入口应报错，避免把带模拟的文件标作 release。
