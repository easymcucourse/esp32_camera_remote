# 2026-10-03 显示阶段计时与黑边清理

## 范围与实现

本轮继续完整缺项；新增开发版 `display bench`、真实 JPEG 路径分阶段计时及堆低水位 / 最大空闲块，优化全宽原尺寸路径的清零和解码器生命周期。该基准在实际 LCD 上显示合成 JPEG，不能证明真实相机网络取景达到目标帧率。

`JPEG phases us` 每约五秒记录锁等待、清零、头部准备、解码、设置页行距搬移、叠加层和 LCD 发布；`LIVEVIEW read` 仍表示相机取景事务耗时。健康日志每十秒及 `status` 输出 IDF 的内部 RAM / PSRAM 低水位和最大空闲块，包含启动及基准的临时分配，未作三十分钟稳定性验收。

全屏原尺寸、全宽且输出对齐时，解码会覆盖图像矩形，包括旧叠加层；仅清除上下黑边。设置页 / ROM 路径继续完整清零，错误帧不发布。切换路径时先释放未使用的解码器，最多保留一个实例。

基准运行于 core 1、优先级 4、32 KiB PSRAM 栈，先获取相机维护 lease 并排空网络 / JPEG 任务。固定图案编码为 1024×576、4:2:2、质量 80，JPEG 38523 字节，二十帧计时包含绘制 / 发布和一 tick 让出；不包括编码及相机网络。临时 SIM 标签，结束清除并恢复连接画面 / 先前相机任务，不改 NVS。启动完成前、维护模式、已有 SIM 或重复请求拒绝；生产固件保留空命令桩，无合成编码路径。

最终 `tools/uart_scripts/display-bench.uart` 13条命令通过：`build/display-profile-final-test.log`，三次二十帧全部成功，全屏6.51 / 6.55FPS、设置页3.26FPS；完整状态恢复为full / settings0 / SIM0 / 维护关闭 / 相机自动等待。行距搬移约27ms，设置页解码约161ms、叠加约25ms；全屏清零约0.4–0.9ms。此前 `build/display-stride-test.log` 亦13条通过，设置页3.27FPS。对比首次全屏4.75、设置页2.75的合成图数据，支持局部性能改善，仍非真实取景目标验收。

`build/display-stride-test.log` 基准前曾观察真实相机会话1、相机电量22% / AF-C / 状态FPS3.6；实际网络窗口2.81FPS，JPEG178897字节、read1100ms、display261ms。基准启动排空42个真实帧且无丢帧，支持在线排空路径，不能据此宣称真实网络≥5FPS。最终验证窗口相机离线；物理画面、ROM路径及长时仍待验收。

## 验收边界与其他问题

COM8 只写已确认运行的 ota_1 应用（偏移0x620000），保留 otadata、另一槽和 NVS；ATOM未烧录。初始预检曾观察真实相机 session1、电量28% / AF-C / 3.3FPS；后续一次行距版测试亦观察真实取景，最终校验版的基准窗口相机离线。真实帧率采样有限，未证明达到目标。合成图相同且使用正常发布等待，支持局部性能比较；不证明镜头动作、真实图像视觉正确、所有尺寸 / ROM路径、生产固件实机或长期稳定性。
