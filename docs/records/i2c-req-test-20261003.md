# 2026-10-03 ATOM 原始 I²C 请求回归

## 实现

ATOM 开发构建支持 `i2c req`，严格解析 9 字节十六进制；一次一个挂起请求，异步排入现有 I²C owner 任务，复用协议 receiver 与响应构造。控制台只收发队列；虚拟请求不写实际 TX FIFO、不刷新 LCD 心跳、不计真实监视统计、不消耗故障计数。POLL 仍执行真实事件 ACK，LCD 在线时打印 SIM WARN。生产关闭模拟时不注册此命令。

## 验证

38 / 38 CTest 通过；新增 debug_hex 连写 / 分隔 / 奇数半字节 / 非法字符 / 长度边界回归。ATOM 开发与关闭模拟构建通过；关闭模拟 ELF 中无 debug_hex_bytes、debug_requests、next_debug_token 或 atom_fault_take 符号。

本轮仅烧录 ATOM COM6（115200），保留 LCD COM8 上一轮固件，未擦除 NVS。`atom-i2c-req.uart` 12 条命令通过：HELLO 连写及分隔、错误 CRC、错误版本、未知命令、POLL、无帧头、短帧 / 奇数分隔 / 非十六进制 / 空参数。六个实际响应逐帧核对长度与 CRC8 全部正确；NO_RESPONSE 不产生伪响应。LCD 在线时警告已观察，完成后 invalid=0、SIM=0。

随后 `pair-i2c-fault.uart` 19 条和 `pair-pad-sim.uart` 18 条命令通过，证明此次任务改动未破坏测试覆盖的真实 I²C 故障恢复及模拟输入路径。结束注入清零、日志关闭、SIM=0、SETTINGS=0。

本地证据：`build/req-host-test.log`、`build/req-atom-build.log`、`build/req-release-build.log`、`m5_atom_matrix/build/flash-i2c-req.log`、`build/atom-i2c-req-test.log`、`build/req-pair-fault-test.log`、`build/req-pair-pad-test.log`。

## 边界

没有拔下 LCD 单独测试；未专门验证携带非零 ACK 的虚拟 POLL 与真实事件竞争。POLL ACK 副作用是源码事实，本轮采用 ACK=0。ATOM 本轮 status 显示 DS4 connected=1、电量未知、输入中立，不能据此确认真实按键或电量上报。相机在线控制、UI / Matrix 物理视觉、取景负载与 30 分钟稳定性仍待验收。LCD 本地模拟与灯阵调试继续待实现。
