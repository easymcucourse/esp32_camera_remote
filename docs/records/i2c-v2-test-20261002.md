# I²C v2 与 Matrix 实机回归（2026-10-02）

设备：LCD ESP32-S3（COM8）、ATOM ESP32-PICO-D4（COM6）；ESP-IDF 5.5.1。两端刷写 bootloader、分区表和 app，未擦除 NVS。相机未连接，本次不验证拍照、录像、变焦或参数切换的相机效果。

## 首轮：新从机与 Matrix

- 两端构建和刷写校验成功，HELLO 成功。
- ATOM 新从机初始化、异步 HID 初始化及应用 ready 成功。
- 同时复位并记录 35 秒串口；DS4 约第 23 秒连接后，LCD 记录 58 次事务重试、一次链路离线、随后重新 HELLO。
- 未观察到 panic、assert 或 RMT 故障日志。高频输入下链路稳定性未通过。
- 本机原始证据：`build/v2-lcd-boot.log`、`build/v2-atom-boot.log`（构建输出不提交）。

## 第二轮：回复任务与中断优先级

ATOM 回复任务固定 core 0、优先级 24，I²C 中断优先级 3，Matrix 渲染任务固定 core 1、优先级 2；LCD 增加失败响应头与 CRC 诊断。

- 两端重新构建、刷写成功，同时复位并记录 65 秒。
- LCD 第 7.765 秒记录一次事务重试：头 `5a`、版本 2、序号 111、POLL 命令与载荷长度 28 均匹配，但 CRC 为 `ff`、计算值为 `dd`。
- ATOM 在这一时间附近保存 DS4 自动重连信息。Flash 写入使未配置 IRAM 的中断暂时不能运行，与超过 32 字节硬件 FIFO 的响应尾部丢失相符；这是待复测的原因推断。
- 余下观察窗口持续收到控制器快照，未发生链路离线。单次 CRC 错误仍不满足稳定性验收。
- 本机原始证据：`build/v2-lcd-priority.log`、`build/v2-atom-priority.log`。

## 后续修正及验收边界

开启 ATOM `CONFIG_I2C_ISR_IRAM_SAFE`，接收回调标记 `IRAM_ATTR`；驱动中断及其对象使用内部 RAM，避免 NVS 写入阻塞 FIFO 尾部补充。构建与刷写成功，app 大小 `0xadd10`。

LCD 持续运行并记录串口，ATOM 单独复位后 LCD 在约 295.261 秒判定链路离线，296.279 秒重新 HELLO（新 boot_id `1371334231`）；取景随后继续输出帧统计。未实际按住扳机或肩键，不能据此声称相机释放命令已在实机验证。该轮 DS4 自动重连仍没有有效报告，蓝牙连接失败后回到扫描；因此 IRAM 修正后的高频输入与 NVS 保存窗口尚未复现，不能宣称 CRC 问题已消除。本机证据：`build/v2-lcd-iram.log`、`build/v2-atom-iram.log`。

统一主机 22 项测试通过，包括新映射、条件 MF、发送缓冲替换与 Matrix 模型。主机模拟不能证明真实 ISR 时序、四角 LED 物理映射或相机动作。仍需独立 ATOM 复位恢复、LED 视觉检查、故障注入和 30 分钟整机稳定性测试。
