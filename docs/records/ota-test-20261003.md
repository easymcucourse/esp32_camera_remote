# 2026-10-03 双分区 OTA

本轮接入三个 OTA 接口、离线页面文件选择 / 版本对比 / 二次确认 / 浏览器发送进度，以及 LCD 实收进度。上传重新校验头部，复用或取得相机维护 lease，使用 IDF 顺序擦除 / 写入 / 完整 SHA256 校验；只有完整验证通过才设置下一启动分区。失败保留当前运行分区和网页，可在同一登录会话重试。HTTP 服务串行处理上传，上传中的状态查询需等处理完成；网页使用 XHR 发送进度，进度 100% 不等于镜像验证成功。

## 分区与启动

NVS 保持 `0x9000` / `0x6000`；otadata 在 `0xF000` / `0x2000`，PHY `0x11000`，ota_0 / ota_1 位于 `0x20000` / `0x620000`、各 6 MiB，未用 data 从 `0xC20000` 起。首次 USB 烧录完整 bootloader、分区表、OTA 初始元数据和 ota_0：`build/flash-ota-migration.log`。未擦除 NVS，迁移前后 `wifi show` 和 `ui info` 可见配置 / 显示档位一致：`build/ota-before-migration.log`、`build/ota-after-migration.log`。

回滚由 IDF bootloader 管理。新镜像首次启动为 pending_verify；app 初始化成功后，在 internal-stack health 中每秒检查堆完整性，连续六十秒并且热点网络接口可用后标为 valid。相机或 ATOM 在线不是确认条件。另一个槽的 ABORTED 状态反映回退诊断，`last_ota` 不是完整持久化更新历史。

## 并发修正与验收边界

复查发现关闭维护已进入 httpd_stop 时，HTTP 上传若同时等待维护任务授权，可能互等。维护关闭先公布 closing 标志再检查 uploading；上传先声明占用，再确认没有关闭 / 终止 / 已退出，才请求 lease；授权等待设五秒上限。`build/flash-ota-admission.log` 只重刷已确认 ota_0 应用，保留 OTA 元数据与另一槽，用于部署该修正。

修正后的最终设备测试 `build/ota-admission-online-upload-test.log`：21 请求通过，损坏 / 有效镜像每份 3438416 字节。测试开始已是相机真实 session=1、非模拟、取景 FPS 约 2.0，相机电量 34% / Focus `0x8004`（当前表为 AF-C）；`maint on stop` 后观察 JPEG worker drained、Camera task finished 和 lease acquired，随后完整 OTA 成功进入 ota_1 / pending_verify。先前离线断言脚本 `ota-admission-upload-test.log` 因相机刚加入而退出，未执行上传；去掉过时离线前提，仍通过 STOP 排空后才上传。

最终等待脚本 `ota-admission-confirm-test.log` 开始监听时镜像已运行约 86 秒，因期待过去已发出的确认日志而超时，不能据此判定确认失败。该窗口实际取景已恢复并持续输出约 2–3 FPS，证明相机自动连接恢复及配对仍可用；随后受控复位仍启动 ota_1 / valid：`build/ota-final-stable-reset-test.log`，配置与 full 保持。首次六十秒确认日志已有 `ota-confirm-test.log` 直接证据，最终版确认通过持久化状态与复位保持验证。最终版的关闭 / 上传相撞整机注入仍未执行，只有保护代码与正常上传路径验证。

完整校验 / 切换和启动元数据提交成功后，即使最后 HTTP 回执丢失也会重启；接收中断 / 校验失败不选择新镜像。实际断网发送失败、接收中断 / 掉电 / Flash 写失败、关闭竞争和超时整机路径仍待注入。前三轮相机会话为 0；最终版已观察真实取景排空和重连，但未让手柄持续 held S1 / S2 / zoom，不证明这些实际动作释放。没有手机空口、浏览器 / LCD 视觉或三十分钟稳定性证据；2–3 FPS 窗口低于帧率目标，不能称性能验收通过。NVS 保留及实际相机重连支持配对未被清除，不是所有键值的逐字节对比。BLE Xbox、电量真实来源、对焦框 / 变焦状态及其他完整需求继续推进。
