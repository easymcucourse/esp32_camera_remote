# UART 调试需求

本文定义 LCD 和 ATOM 的 UART 调试控制台：通过串口输入命令查看状态、模拟 LCD ↔ ATOM 的 I²C 通信、模拟手柄动作和注入故障。目的是在没有手柄、没有 ATOM 或没有 LCD 的情况下，也能单独开发和测试每一端，并让测试可以用脚本重复执行。

> 双端行输入、help / version / status / log、请求号与脚本回放已实现；LCD 保留旧相机命令及 wifi / factory，显示回调故障注入已实测。ATOM 手柄模拟 / 动作序列及真实 I²C 切页、模拟量、溢出保护已实测；双端 I²C 监视 / 分类统计已接入并实测；ATOM CRC / 丢响应 / 延时已实测；ATOM `i2c req` 已实现；Matrix 四角校准和故障图案已实现，LCD 本地模拟及输入 / 故障 / 物理心跳暂停恢复已实测。当前命令见 [串口手册](../user-guide/serial.md)，后续语法可调整，但须保持两端风格一致。

## 现状

| 设备 | 当前串口输入 |
| --- | --- |
| LCD（UART0，115200） | debug_console 按行接收、Enter 执行；最多 255 字节，支持引号 / 转义，兼容 j / s / S / p / u，并支持 help、wifi 与两级 factory 重置 |
| ATOM（UART0，115200） | debug_console 按行接收，支持 help / version / status / log 与请求号 |

ATOM 已支持手柄模拟、原始请求与故障注入，可脚本回放。LCD 支持本地 ATOM 模拟，经同一协议客户端和输入路径验证，本地回放已实测。

## 范围

- 包括：两端的命令行控制台、状态查询、I²C 通信模拟与监视、手柄动作模拟、故障注入、命令脚本回放。
- 不包括：通过 Wi-Fi 或蓝牙远程调试；模拟相机（PTP/IP 模拟相机见 [测试与持续集成设计](../development/testing.md#4-故障注入)）。

## 需求

### 1. 控制台通用要求

- **R1.1** 两端都在 UART0（115200）提供按行输入的命令控制台，与日志输出共用同一串口。
- **R1.2** 兼容 LCD 现有的单字符命令：一行只有 `j`、`s`、`S`、`p` 时，行为与现在相同。`tools/serial_log.py --command` 现有用法不受影响。
- **R1.3** 每条命令都有一行结果输出，以 `OK` 或 `ERR <原因>` 开头，便于脚本用 `--until` 判断；输出带统一前缀（例如 `[dbg]`），与普通日志区分。
- **R1.4** 提供 `help`（列出命令和语法）、`version`（固件版本、编译时间、协议版本）、`status`（见第 2 节）。
- **R1.5** 输入时日志照常滚动，命令不得因日志交错而失效；提供 `log <tag> <level>` 临时调整日志级别，减少干扰。
- **R1.6** 命令处理不得阻塞 I²C、蓝牙、取景等实时任务；控制台任务优先级低于这些任务。
- **R1.7** 模拟和故障注入类命令可以通过编译选项（Kconfig）整体关闭；开发阶段默认开启。
- **R1.8** 所有模拟状态只保存在 RAM 中，重启后自动恢复为正常模式。

### 2. 状态查询

- **R2.1** LCD `status` 输出：相机链路状态与最近一次失败原因、取景 FPS、ATOM 链路状态（在线、协议版本、`boot_id`、连续失败次数）、DS4 状态与当前按键位图、扳机和摇杆值、最近确认的事件 ID、内存余量、当前是否处于模拟模式。
- **R2.2** ATOM `status` 输出：LCD 链路状态（最近一次合法命令距今时间、非法命令计数）、DS4 链路状态与当前输入、事件缓存使用量和溢出计数、云台链路状态（实现后）、灯阵当前显示的图案和故障位、当前是否处于模拟模式。

### 3. LCD 端：模拟 ATOM 与手柄

用于在没有 ATOM 和手柄时调试 LCD 的界面、相机控制和手柄输入处理。

- **R3.1** `atom sim on|off`：开启后 LCD 不再访问 I²C 总线，改用模拟的 ATOM；关闭后恢复真实链路。模拟数据从 I²C 解码之后的位置注入，之后的处理路径（事件去重、按键边沿、扳机状态机、安全释放）与真实链路完全相同。
- **R3.2** 模拟 ATOM 的链路状态：
  - `atom online` / `atom offline`：ATOM 上线或离线（离线时应触发与真实断开相同的安全释放）；
  - `atom reboot`：模拟 ATOM 重启（`boot_id` 变化）；
  - `atom version <n>`：模拟协议版本不匹配（版本 2 实现后）。
- **R3.3** 模拟 DS4 和云台状态：`pad connect` / `pad disconnect`；`pad battery <0-10|none>`；`gimbal state <off|search|connecting|connected>`。
- **R3.4** 模拟手柄动作（见第 5 节命令格式），包括单次点按、按住、松开、组合键、摇杆、扳机，以及带延时的动作序列。
- **R3.5** 模拟事件缓存行为：`pad gap`（下一个事件带 `gap` 标志）、`pad overflow`（模拟溢出故障位），用于验证 LCD 不会根据丢失的边沿触发拍照或录像。
- **R3.6** 模拟 I²C 故障：`atom fail <n>`（接下来 n 次事务失败）、`atom crc <n>`（n 次 CRC 错误）、`atom timeout <n>`（n 次超时），用于验证“连续 3 次失败才判定断开”和重试时 `seq` / `ack_id` 不变。

### 4. ATOM 端：模拟手柄与 LCD 主机

用于在没有手柄时测试 LCD 与 ATOM 的真实 I²C 链路，以及在没有 LCD 时测试 ATOM 的从机协议。

- **R4.1** `pad sim on|off`：开启后忽略真实 DS4 输入，改用串口模拟的手柄状态；模拟输入写入与蓝牙回调相同的状态快照和事件缓存，LCD 通过真实 I²C 读到，与真实手柄无法区分。
- **R4.2** 支持与 LCD 端相同的手柄动作命令（第 5 节），以及 `pad connect` / `pad disconnect` / `pad battery`。
- **R4.3** 左摇杆和 L3 的模拟输入同样交给云台模块处理（实现后），用于在没有手柄时调试云台。
- **R4.4** `i2c req <hex>`：把一帧请求当作来自 LCD 主机交给从机协议处理，并以十六进制打印生成的响应帧。用于在没有 LCD 时测试协议解析、CRC 校验、重新同步和各种结果码。
- **R4.5** 从机故障注入：`i2c drop <n>`（接下来 n 次不响应）、`i2c corrupt <n>`（n 次响应 CRC 错误）、`i2c delay <ms>`（响应延迟），用于在 LCD 端验证断开判定和重连。
- **R4.6** 事件缓存故障注入：`pad overflow`（立即制造一次溢出），用于验证灯阵溢出提示和 LCD 的 `gap` 处理。
- **R4.7** 灯阵调试：`led test`（四角校准图）、`led fault <bt|i2c|overflow> on|off`（强制显示异常图案），用于对照 [Matrix LED 状态显示需求](matrix-led-request.md) 检查图案。

### 5. 手柄动作命令

两端使用相同的命令格式。

- **R5.1** 按键名称同时接受 Xbox 布局名称和 DS4 名称（对照见 [手柄控制方案](gamepad-request.md)），不区分大小写：

  | 名称 | 等价 DS4 名称 |
  | --- | --- |
  | `a` `b` `x` `y` | `cross` `circle` `square` `triangle` |
  | `lb` `rb` | `l1` `r1` |
  | `select` `start` | `share` `options` |
  | `up` `down` `left` `right` | 同左 |
  | `l3` `r3` `ps` `touch` | 同左 |

- **R5.2** 按键动作：

  | 命令 | 行为 |
  | --- | --- |
  | `tap <键>[+<键>…] [ms]` | 按下后保持 ms（默认 100）再松开；多个键同时按下 |
  | `hold <键>[+<键>…]` | 按下并保持 |
  | `release <键>…\|all` | 松开指定键或全部 |

- **R5.3** 模拟量：

  | 命令 | 行为 |
  | --- | --- |
  | `stick <l\|r> <x> <y>` | 设置摇杆，范围 -128..127；`stick r 0 0` 回中 |
  | `trigger <lt\|rt> <0-255\|half\|full\|off>` | 设置扳机；`half`、`full` 分别取半压、全压阈值中间的典型值 |
  | `shoot` | RT 依次半压、全压、半压、松开，每步默认 200 ms |
  | `record` | LT 依次半压、全压、松开 |

- **R5.4** `seq <动作>; <动作>; …`：在一行内按顺序执行多个动作，`wait <ms>` 插入延时。例如 `seq hold rt; wait 300; trigger rt full; wait 200; release all`。
- **R5.5** 每次模拟输入都生成与真实手柄相同的事件（按键位图变化入事件缓存）；摇杆和扳机的变化只更新快照，不产生事件，与真实规则一致。
- **R5.6** 时间精度：`tap`、`wait` 的实际时长误差不超过 ±20 ms。

### 6. I²C 通信监视

- **R6.1** 两端提供 `i2c log on|off`：开启后以十六进制打印每一帧请求和响应，并标注方向、序号、命令和结果。
- **R6.2** 由于在线时约每 50 ms 一次事务，提供 `i2c log changes`：只打印与上一帧内容不同的帧，以及所有失败的事务。
- **R6.3** `i2c stats`：输出事务总数、失败数（按超时、CRC、头部、序号分类）、最长响应时间，并可用 `i2c stats reset` 清零。

### 7. 安全与可见性

- **R7.1** 处于任何模拟模式时，LCD 在连接页和状态栏显示 `SIM` 标记；ATOM 每条模拟相关日志带 `SIM` 前缀，`status` 中明确显示。
- **R7.2** 模拟的拍照、录像会真实发送给已连接的相机；`shoot`、`record` 命令执行前在日志中提示。
- **R7.3** 退出模拟模式（`atom sim off`、`pad sim off`）时，先释放所有模拟中按下的键和扳机，再恢复真实输入，不得遗留 S1/S2 或变焦。

### 8. 脚本回放

- **R8.1** 新增主机工具（例如 `tools/uart_script.py`），读取命令脚本文件逐行发送，支持注释、`wait <ms>`、`expect <文本> [超时]`（等待日志出现指定文本，超时则失败），并像 `serial_log.py` 一样把完整日志写入文件。
- **R8.2** 脚本执行失败时返回非 0 退出码，便于用于自动化测试。
- **R8.3** 仓库提供常用测试脚本，例如：扳机交叉按压与释放、ATOM 断开时的安全释放、连续切换曝光 Mode、I²C 连续失败与恢复。

## 验收测试

- LCD 不接 ATOM：`atom sim on`、`pad connect`、`tap start`，界面在预览和设置间切换；`tap lb` 切换曝光 Mode。
- LCD 模拟扳机交叉按压（RT 半压 → LT 半压 → RT 松开 → LT 松开）：日志显示 RT 半压按下 S1、RT 松开立即释放 S1，LT 不产生 S1 命令。
- LCD 模拟 RT 按住时执行 `atom offline`：日志显示立即释放 S2、S1。
- LCD 执行 `atom fail 2`：链路不判定断开；`atom fail 3`：判定断开并在恢复后重连。
- ATOM 不接手柄：`pad sim on`、`tap start`，LCD 通过真实 I²C 收到事件并切换界面。
- ATOM 不接 LCD：`i2c req` 输入一帧正确请求，打印正确响应；输入 CRC 错误的请求，返回 `BAD_CRC`。
- ATOM 执行 `i2c drop 3`：LCD 判定断开并在之后自动恢复。
- ATOM 执行 `pad overflow`：灯阵显示溢出图案，LCD 不触发任何按键动作。
- 模拟模式下 LCD 显示 `SIM` 标记；重启后自动退出模拟模式。
- `tools/uart_script.py` 运行仓库提供的全部测试脚本，均返回 0。
